# PPT Bridge 基础设施稳定性改进方案

## 设计原则

1. **Agent 自由度优先**
   - 不限制 agent 的创造力和决策
   - 工具失败时自动修复，对 agent 透明
   - 错误信息清晰，帮助 agent 自主恢复

2. **基础设施零容忍**
   - 桥接层、心跳、状态同步必须 100% 可靠
   - 单点故障自动恢复，无需人工介入
   - 降级策略清晰，性能可预测

3. **可观测性**
   - 关键路径有日志和监控
   - 错误有明确的诊断信息
   - 性能指标可追踪

---

## 🔧 关键改进项（按优先级）

### 1. 进程管理和端口占用（高优先级）

**问题**：
- `taskkill //F //IM node.exe` 会杀死所有 node 进程（包括无关的）
- 单实例锁文件可能残留
- 端口冲突时没有自动清理

**解决**：
- 用 PID 精确管理进程
- 启动时记录 PID，重启时只杀自己的子进程
- 端口占用时检查是否是旧实例，是则清理，否则报错
- 锁文件加入 PID + 时间戳，启动时自动验证

### 2. 编辑器心跳可靠性（高优先级）

**问题**：
- 后台标签页心跳停止
- Worker 失败后没有自动修复
- MCP 工具不知道心跳状态

**解决**：
- Web Worker 心跳 + 主线程降级双保险
- Worker 连续失败自动降级，恢复后自动回切
- MCP 工具检测到心跳停止时，主动触发编辑器"唤醒"机制
- 添加心跳健康检查端点，relay 可以探测编辑器状态

### 3. 状态同步可靠性（中优先级）

**问题**：
- pushState 失败静默，deck 可能不同步
- 没有状态版本号，不知道是否最新

**解决**：
- pushState 失败重试 3 次，仍失败则告警
- 添加 state_version，编辑器定期校验是否同步
- MCP 工具调用前检查 deck 是否为空，空则返回友好错误

### 4. 浏览器缓存和版本管理（中优先级）

**问题**：
- 手动刷新才能更新 JS
- 没有版本号，不知道是否最新

**解决**：
- JS 文件加 hash 版本号（app.js?v=abc123）
- index.html 添加 no-cache 头
- 编辑器启动时检查版本，不匹配自动提示刷新

### 5. 构建流程自动化（低优先级）

**问题**：
- heartbeat-worker.js 需要手动复制

**解决**：
- 构建脚本自动复制 Worker 文件
- 添加构建完整性检查
