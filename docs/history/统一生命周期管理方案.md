# 统一生命周期管理方案

## 问题

当前 dshd 启动的服务：
- 使用 `detached: true` 分离进程
- 输出重定向到日志文件
- 生命周期独立管理
- 容易变成孤儿进程

## 理想模式

**所有服务与终端窗口的生命周期绑定：**
- 终端打开 → 所有服务启动
- 终端关闭 → 所有服务停止
- 日志可见（或统一管理）
- 不会产生孤儿进程

## 解决方案

### 方案 1：前台进程树（推荐）

```javascript
import { spawn } from 'child_process';
import { createWriteStream } from 'fs';

class ForegroundServiceManager {
  constructor() {
    this.services = [];
    this.logStreams = new Map();
    this.setupCleanup();
  }

  // 启动服务，但不分离
  startService(name, cmd, args, options = {}) {
    const logFile = options.logFile || `/dev/null`;
    const logStream = createWriteStream(logFile, { flags: 'a' });
    
    const child = spawn(cmd, args, {
      ...options,
      stdio: options.showOutput 
        ? 'inherit'  // 输出到终端
        : ['ignore', logStream, logStream],  // 写入日志
      detached: false,  // ❌ 不分离！
    });

    // 实时转发日志到终端（可选）
    if (options.logToConsole && !options.showOutput) {
      const tail = spawn('tail', ['-f', logFile]);
      tail.stdout.on('data', (data) => {
        console.log(`[${name}] ${data.toString().trim()}`);
      });
    }

    child.on('exit', (code) => {
      console.log(`[${name}] 退出，代码: ${code}`);
      logStream.end();
    });

    this.services.push({ name, child, logStream });
    return child;
  }

  // 设置清理处理
  setupCleanup() {
    const cleanup = () => {
      console.log('\n正在停止所有服务...');
      
      // 关闭所有子进程
      this.services.forEach(({ name, child }) => {
        try {
          child.kill('SIGTERM');
          console.log(`✓ 已停止 ${name}`);
        } catch (e) {
          console.error(`✗ 停止 ${name} 失败:`, e.message);
        }
      });

      // 关闭日志流
      this.logStreams.forEach(stream => stream.end());

      process.exit(0);
    };

    // 捕获所有退出信号
    process.on('SIGINT', cleanup);   // Ctrl+C
    process.on('SIGTERM', cleanup);  // kill
    process.on('SIGHUP', cleanup);   // 终端关闭
    
    // Windows 特殊处理
    if (process.platform === 'win32') {
      process.on('SIGBREAK', cleanup);
    }
  }

  // 等待所有服务退出
  async waitAll() {
    await Promise.all(
      this.services.map(({ child }) => 
        new Promise(resolve => child.on('exit', resolve))
      )
    );
  }
}

// 使用示例
const manager = new ForegroundServiceManager();

// 启动所有服务
manager.startService('broker', 'node', ['broker.mjs'], {
  logFile: './logs/broker.log',
  logToConsole: true,
});

manager.startService('dsh', 'node', ['auth-proxy.mjs'], {
  logFile: './logs/dsh.log',
  logToConsole: true,
});

manager.startService('ppt-workbench', 'node', ['ppt-workbench.mjs'], {
  logFile: './logs/ppt.log',
  logToConsole: true,
});

console.log('所有服务已启动。按 Ctrl+C 停止所有服务。');

// 保持运行直到所有服务退出
await manager.waitAll();
```

### 特点

1. **统一生命周期**
   - 所有子进程 `detached: false`
   - 父进程退出 → 子进程自动收到信号
   - 终端关闭 → 整个进程树终止

2. **清晰的日志**
   - 每个服务有独立日志文件
   - 可选：实时转发到终端（带服务名标记）
   - 或者直接 `stdio: 'inherit'` 共享终端

3. **优雅关闭**
   - 捕获 SIGINT/SIGTERM/SIGHUP
   - 依次停止所有服务
   - 等待清理完成

4. **无孤儿进程**
   - 进程树结构清晰
   - 操作系统自动清理

### 方案 2：显式进程组管理

```javascript
import { spawn } from 'child_process';

class ProcessGroupManager {
  constructor() {
    this.pgid = process.pid;  // 使用主进程 PID 作为进程组 ID
    this.children = [];
  }

  startService(name, cmd, args) {
    const child = spawn(cmd, args, {
      detached: false,
      stdio: 'inherit',
    });

    // 将子进程加入进程组
    try {
      process.kill(-this.pgid, 0);  // 检查进程组
    } catch (e) {
      // 创建新进程组
      process.setpgid(0, 0);
    }

    this.children.push({ name, pid: child.pid });
    
    child.on('exit', (code) => {
      console.log(`[${name}] 退出: ${code}`);
    });

    return child;
  }

  // 停止整个进程组
  stopAll() {
    try {
      // 向整个进程组发送 SIGTERM
      process.kill(-this.pgid, 'SIGTERM');
      console.log('已停止进程组');
    } catch (e) {
      console.error('停止进程组失败:', e.message);
    }
  }
}

// 使用
const manager = new ProcessGroupManager();

manager.startService('broker', 'node', ['broker.mjs']);
manager.startService('dsh', 'node', ['dsh.mjs']);
manager.startService('ppt', 'node', ['ppt.mjs']);

process.on('SIGINT', () => {
  manager.stopAll();
  process.exit(0);
});
```

## 对比：当前 vs 理想

| 方面 | 当前 (detached) | 理想 (前台进程树) |
|------|----------------|-------------------|
| 生命周期 | 独立，需要状态文件追踪 | 统一，与终端绑定 |
| 孤儿进程 | ❌ 容易产生 | ✅ 不会产生 |
| 清理 | ❌ 需要手动 kill PID | ✅ 自动清理 |
| 日志 | 分散在各自文件 | 统一管理或实时显示 |
| 复杂度 | 高（状态管理、锁文件） | 低（操作系统管理） |
| 可见性 | 后台运行，不可见 | 前台运行，可见 |
| 守卫兼容 | ❌ 需要绕过 | ✅ 完全符合 |

## 建议

### 短期（修复当前问题）

在 dshd 的 `launcher.mjs` 中：
1. 不使用 `detached: true`
2. 不使用 `child.unref()`
3. 添加严格的清理逻辑

### 长期（重构）

创建统一的服务管理器：
1. 所有服务在同一个进程树下
2. 终端关闭 = 所有服务停止
3. 日志统一管理（但可以分文件）
4. 符合前台运行守卫原则

## 总结

你的观察是对的：

> "为什么这些被启动程序根据启动清单打开的程序没有统一管理，生命周期还是各管各的？"

**当前设计确实有问题！**

理想情况下：
- ✅ 一个终端窗口
- ✅ 一个主进程（dshd）
- ✅ 多个子服务（非 detached）
- ✅ 终端关闭 → 全部停止
- ✅ 符合"终端窗口的生命周期 = 程序的生命周期"原则

这需要重构 `tools/dsh-launcher/lib/launcher.mjs` 的启动逻辑。
