# 统一服务管理架构 - 大道至简

## 🎯 核心理念

> **不要将服务直接绑定到具体的实现（终端、GUI等），而是绑定到统一的抽象管理器**

## 📐 架构设计

```
                    ServiceManager
                   (核心抽象层)
                         ↓
        统一管理所有服务的生命周期
        - 启动/停止/重启
        - 状态查询
        - 依赖管理
        - 事件通知
                         ↓
        ┌────────────────┼────────────────┐
        ↓                ↓                ↓
  TerminalInterface  HttpApiInterface  GuiInterface
   (终端视图)         (HTTP API)       (图形界面)
        ↓                ↓                ↓
   用户交互          程序调用          可视化控制
```

## ✨ 关键特性

### 1. **解耦**
- 核心逻辑在 `ServiceManager`
- 接口只是"视图"，可随意替换
- 终端、API、GUI 都控制同一个管理器

### 2. **统一**
- 所有服务通过统一接口管理
- 一致的生命周期管理
- 统一的状态查询

### 3. **简单**
- 一个抽象统领一切
- 不需要复杂的状态文件
- 不需要 PID 追踪和锁文件

### 4. **扩展**
- 轻松添加新的接口实现
- 不影响核心逻辑
- 不影响其他接口

## 🔧 使用示例

### 基础用法

```javascript
import { createServiceManager } from './lib/service-manager.mjs';
import { runInTerminal } from './lib/terminal-interface.mjs';

// 1. 创建管理器
const manager = createServiceManager({
  logDir: './logs',
});

// 2. 注册服务
manager.register('broker', {
  command: 'node',
  args: ['broker.mjs'],
  depends: [],  // 无依赖
});

manager.register('dsh', {
  command: 'node',
  args: ['dsh.mjs'],
  depends: ['broker'],  // 依赖 broker
});

manager.register('ppt-workbench', {
  command: 'node',
  args: ['ppt-workbench.mjs'],
  depends: ['broker', 'dsh'],  // 依赖多个服务
});

// 3. 启动所有服务（自动按依赖顺序）
await manager.startAll();

// 4. 使用接口（终端）
await runInTerminal(manager);
```

### 使用 HTTP API 接口

```javascript
import { serveHttpApi } from './lib/http-api-interface.mjs';

// 同一个管理器，不同的接口
serveHttpApi(manager, 9000);

// 现在可以通过 HTTP 控制：
// curl http://localhost:9000/status
// curl -X POST http://localhost:9000/start/ppt-workbench
// curl -X POST http://localhost:9000/stop/ppt-workbench
```

### 同时使用多个接口

```javascript
// 一个管理器，多个视图
const manager = createServiceManager({ logDir: './logs' });

// ... 注册服务 ...

await manager.startAll();

// 终端接口（主线程）
const terminal = runInTerminal(manager);

// HTTP API（后台）
serveHttpApi(manager, 9000);

// GUI（如果实现了）
// showGui(manager);

await terminal;
```

## 🎨 添加新接口

只需实现一个新的接口类：

```javascript
export class MyCustomInterface {
  constructor(manager) {
    this.manager = manager;
    this.setupListeners();
  }

  setupListeners() {
    // 监听管理器事件
    this.manager.on('service:started', ({ name, pid }) => {
      // 你的逻辑：通知用户、更新 UI 等
    });

    this.manager.on('service:stopped', ({ name }) => {
      // 你的逻辑
    });
  }

  // 提供你的控制方法
  async startService(name) {
    await this.manager.start(name);
  }

  async stopService(name) {
    await this.manager.stop(name);
  }

  getStatus() {
    return this.manager.getStatus();
  }
}
```

## 🆚 对比：旧 vs 新

| 方面 | 旧架构（detached） | 新架构（统一管理器） |
|------|-------------------|---------------------|
| **核心** | 分散的进程管理 | ServiceManager 统一抽象 |
| **生命周期** | 各自独立 | 管理器统一控制 |
| **状态追踪** | 文件 + PID | 内存中的 Map |
| **清理** | 手动 kill PID | 自动（detached: false） |
| **接口** | 终端硬编码 | 可插拔的接口实现 |
| **扩展性** | 难 | 易（添加新接口） |
| **复杂度** | 高 | 低 |
| **孤儿进程** | 容易产生 | 不会产生 |

## 💡 设计优势

### 1. 关注点分离
- **ServiceManager**: 只关心服务生命周期
- **TerminalInterface**: 只关心终端显示
- **HttpApiInterface**: 只关心 HTTP 请求

### 2. 单一职责
- 每个模块职责清晰
- 易于理解和维护
- 易于测试

### 3. 开放封闭原则
- 对扩展开放：添加新接口
- 对修改封闭：不影响核心逻辑

### 4. 依赖倒置
- 接口依赖抽象（ServiceManager）
- 不依赖具体实现

## 📝 总结

**核心思想**：
> 终端只是恰好最简单的实例，本质是需要一个统一的抽象管理器

**实现**：
- ServiceManager = 核心抽象
- TerminalInterface = 一个视图
- HttpApiInterface = 另一个视图
- 可以无限扩展更多视图

**结果**：
- 结构统一
- 方案简单
- 高度解耦
- 大道至简 ✨
