# dsh-stack v2：一份清单统一 profile / domain 装配（2026-11-03）

> 目标：让 `dshd --stack` 和 domain runtime 共用同一份 `dsh-stack.json`，
> 结束“profile 一套入口、domain 另一套入口”的分裂。

## 一、设计

`dsh-stack.json` 增加 `kind`（缺省 `profile`）：

| kind | 装配来源 | 编译/执行 |
|---|---|---|
| `profile` | `plugins.bundles` + `services[]` | 编译 `<home>/profiles/<profile>/package.json` + `<stateDir>/stack-services.json`，dshd 拉起 broker + dsh |
| `domain` | `domain.source`（`dsh-domain.json`） | 委托 `dsh-suite-kit` 的 `createRuntime/startRuntime`；插件行、suite `services.json`、端口/覆盖项由 domain 决定 |

domain 型示例：

```json
{
  "kind": "domain",
  "name": "ppt",
  "stateDir": "./.dshd/state",
  "ports": { "proxy": "auto", "upstream": "auto", "content": 39311, "broker": "auto" },
  "domain": {
    "source": "../extensions/bridges/ppt-bridge/domains/ppt",
    "runtimeId": "rt-stack-ppt",
    "recreate": false
  }
}
```

端口映射：

- `ports.proxy` → runtime harness 端口（浏览器入口）
- `ports.upstream` → runtime dsh 端口
- `ports.content` → runtime content 端口（PPT relay / 内容服务）
- `ports.broker` → runtime broker 端口
- `ports.services.*` → suite 服务端口偏好（`auto`/0 现场分配）

domain 覆盖项：`domain.requires/scope/model/workspaceController/env`；
`runtimeId` 默认 `rt-stack-<stack slug>`，稳定 id 让 `start/stop/status/doctor`
幂等；`recreate: true` 会先删同名 runtime（破坏性）。

## 二、实现

| 文件 | 变更 |
|---|---|
| `packages/dsh-stack-kit/src/index.mjs` | `kind` 校验；domain 型编译（不编译 profile/services）；`planStack` 返回 `changes.domain`；`applyStack` 对 domain 给出 `DOMAIN_STACK_REQUIRES_LAUNCHER` |
| `packages/dsh-stack-kit/stack.schema.json` | `kind` / `domain` / `ports.content`；`if kind=domain then domain required else home/profile required` |
| `packages/dsh-suite-kit/src/runtime.mjs` | `createRuntime` 新增 `brokerPort` / `servicePorts` 选项；`options.env` 与 `domain.runtime.env` 合并（stack.env 优先） |
| `tools/dsh-launcher/lib/stack.mjs` | `toLauncherConfig` 分 profile/domain；domain 端口/路径映射 |
| `tools/dsh-launcher/lib/domain.mjs` | 新增：`assertDomainConfig`、`describeDomain`、`ensureDomainRuntime`、`applyDomainStack`、`startDomain`、`stopDomain`、`domainStatusRows`、`printDomainStatus/Doctor`、`listDomainLogs`、`superviseDomain` |
| `tools/dsh-launcher/bin/dshd.mjs` | `stack plan/apply` 分 kind；`start/stop/status/doctor/logs` 分 kind；domain `--foreground` 走 `superviseDomain` |
| `tools/dsh-launcher/test/domain-stack.test.mjs` | 新增 E2E：plan→apply→start→status/doctor→stop→复用 |

## 三、验收

| 项 | 结果 |
|---|---|
| `packages/dsh-stack-kit` | **9/9**（新增 2 个 domain 用例） |
| `tools/dsh-launcher/test/domain-stack.test.mjs` | **1/1**（7/7 步骤） |
| `tools/dsh-launcher/test/stack-chain.test.mjs` | **3/3**（profile 栈 14 场景未回归） |
| `test-stack:all` | stack-kit + launchpad + profile E2E + domain E2E |
| `verify-all` | 全量门禁（含 domain E2E） |

domain E2E 实测：

- `stack plan`：`kind=domain`、`changes.domain.exists=false`、domain 摘要（components/services）；
- `stack apply`：创建 runtime + profile（`status=installed`），分配 harness/content/broker/service 端口；
- `start`：真实拉起 dsh + broker + probe-service；harness 200、service `/healthz` 200、discovery running；
- `status`：dsh/broker/service 全 running；`doctor` 退出码 0；
- `stop`：进程与端口释放，status 转 stopped；
- 再次 `start`：复用同一 runtime/端口（幂等）；外部栈 3016/39311/13594/13596 全程不变；
- domain 源码被删/搬走后，`status/stop` 仍可用（只依赖 stateDir 的 runtime 记录，
  不再解析 `domain.source`）。

## 四、边界

1. profile 型仍走“编译 profile + broker 清单”；domain 型走 runtime。两种 kind 共用
   `dshd` 入口，但底层装配路径不同（这是有意的：profile 是“装插件”，domain 是“起一套运行时”）。
2. domain 型的 `.works` 字段（自动启动/健康检查/钩子）仍由 `dsh-deploy` 的部署配置承载；
   stack 只描述 runtime 本身。
3. domain 型的 `--foreground` 是“整组 stop+start”守护，不是进程内热重启。
4. `domain.recreate` 会删除同名 runtime 的 store 内容，默认关闭。
5. 发布/推送仍到本地 `dist/`；远端 publish/CI 未做。
